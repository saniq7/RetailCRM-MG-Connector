# Разбор ошибок

Начните с диагностики — она укажет, на каком звене цепочки проблема:

```bash
retailcrm-mg doctor -v
```

---

## `bootstrap` возвращает 403

**Симптом:** `❌ Forbidden | HTTP 403`

У API-ключа нет прав на integration modules. В RetailCRM откройте
**Настройки → Интеграция → Ключи доступа к API**, найдите ключ и включите
права на раздел «Интеграционные модули» — и чтение, и запись.

Что реально доступно ключу:

```bash
curl -sS "https://crm.example.com/api/v5/credentials?apiKey=$KEY" | python3 -m json.tool
```

В списке должно быть `/api/integration-modules/{code}/edit`.

## `bootstrap` возвращает 404

Причины по убыванию вероятности:

1. Неверный `--base-url`. Нужен адрес именно вашего аккаунта — тот, по которому
   вы заходите в CRM. Заглушки из документации (`crm.example.com`) не работают.
2. Аккаунт использует другой путь API. Проверьте:
   `curl -sS https://crm.example.com/api/api-versions`
3. Код модуля содержит недопустимые символы. Разрешены только `[A-Za-z0-9_-]`;
   коннектор нормализует код сам, но при явном `--module-code` проверьте результат
   командой `retailcrm-mg config`.

## Токен не вернулся

**Симптом:** `❌ RetailCRM принял модуль, но не вернул mgBot-токен`

Модуль создан, но MessageGateway токен не выдал. Проверьте:

1. Подключён ли к аккаунту MessageGateway и куплен ли тариф с чатами.
2. Что именно пришло в ответе:
   ```bash
   retailcrm-mg bootstrap --dump-response --no-write
   ```
   Команда покажет пути к полям, похожим на токен (значения замаскированы).
   Если поле нашлось по нестандартному пути — откройте issue, добавим его
   в список известных.
3. Не отключён ли модуль: `retailcrm-mg modules` — колонка `ACTIVE`.

## MG отвечает 401

**Симптом:** `❌ ... | HTTP 401 | .../channels`

Токен недействителен. Почти всегда причина одна: тот же integration module
перевыпустили где-то ещё, и старый токен отозван.

```bash
retailcrm-mg bootstrap --refresh
```

Чтобы это не повторялось, заведите отдельный код модуля для каждого сервера:

```bash
retailcrm-mg bootstrap --module-code mg_connector_prod01 --env-file ~/.mg/prod01.env
```

## Модуль уже существует

**Симптом:** `⚠️ модуль ... уже существует и привязан к MG` и код возврата `2`.

Это защита: перевыпуск токена отзовёт действующий, и работающая интеграция
сломается. Варианты:

- новый модуль: `--module-code <другой_код>`;
- осознанный перевыпуск: `--refresh`.

## Не задан адрес MessageGateway

**Симптом:** `❌ не задан адрес MessageGateway` или предупреждение после `bootstrap`.

RetailCRM не вернул адрес MG в ответе — такое бывает в части версий. Токен при
этом уже выпущен и сохранён, перевыпускать его не нужно. Допишите адрес в `.env`:

```env
RETAILCRM_MG_API_BASE=https://mg.example.com/api/bot/v1
```

Где взять адрес: *Настройки → Интеграция → Чаты* в RetailCRM либо поддержка
RetailCRM. Хватит и голого хоста — путь `/api/bot/v1` коннектор допишет сам:

```bash
retailcrm-mg doctor --mg-api-base mg.example.com
```

## Пустой список каналов

Токен рабочий, но `channels` ничего не отдаёт — в RetailCRM не активирован
ни один канал. Проверьте **Настройки → Интеграция → Чаты**.

## Пустые чаты или сообщения

- Убедитесь, что фильтр не слишком узкий: `--channel-id` без совпадений даёт пусто.
- MG отдаёт данные только по каналам, доступным конкретному боту. Модуль,
  созданный только что, видит переписки с момента подключения.

## Таймауты и обрывы

Увеличьте таймаут и посмотрите логи ретраев:

```bash
RETAILCRM_MG_TIMEOUT=60 retailcrm-mg chats -v
```

Коннектор сам повторяет запросы при `429` и `5xx` с экспоненциальной паузой.
Ошибки `401`, `403` и `404` не повторяются — они не проходят от повтора.

## Где лежит конфигурация

```bash
retailcrm-mg config
```

По умолчанию `~/.retailcrm-mg/.env`. Изменить — `--env-file` или переменная
`RETAILCRM_MG_ENV_FILE`. Права на файл должны быть `600`:

```bash
ls -l ~/.retailcrm-mg/.env
```

## Ничего не помогло

Откройте [issue](https://github.com/saniq7/RetailCRM-MG-Connector/issues)
и приложите:

- вывод `retailcrm-mg doctor -v`;
- вывод `retailcrm-mg config`;
- версии: `retailcrm-mg --version`, `python3 --version`.

**Токены и API-ключи не прикладывайте** — вывод обеих команд уже замаскирован.
