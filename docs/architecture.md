# Архитектура

## Модули

```
src/retailcrm_mg/
├── config.py     конфигурация: .env, переменные окружения, маскирование секретов
├── envfile.py    идемпотентная запись .env без дублей и потери комментариев
├── http.py       HTTP поверх urllib: ретраи, разбор ошибок, вырезание apiKey из URL
├── retailcrm.py  RetailCRM API v5: регистрация модуля и выпуск mgBot-токена
├── mg.py         MessageGateway Bot API: каналы, чаты, диалоги, сообщения
├── export.py     нормализация сообщений и выгрузка в JSON/JSONL/Markdown
└── cli.py        командный интерфейс
```

Зависимости направлены в одну сторону: `cli` → `export`/`mg`/`retailcrm` → `http`/`config`.
Ни один модуль не тянет внешние пакеты.

## Почему ноль зависимостей

Коннектор часто ставят на сервер, где нет ни `requests`, ни возможности собирать
колёса. Стандартной библиотеки хватает: `urllib.request` умеет всё, что нужно,
а собственный слой в `http.py` добавляет ретраи и понятные ошибки.

Побочный плюс — тесты гоняют подменный HTTP-клиент и не ходят в сеть.

## Два разных API

Коннектор работает с двумя независимыми системами.

| | RetailCRM API v5 | MessageGateway Bot API |
|---|---|---|
| Адрес | `https://<аккаунт>/api/v5` | `https://mg.<домен>/api/bot/v1` |
| Аутентификация | `apiKey` в query | `X-Bot-Token` в заголовке |
| Роль | выпуск токена, управление модулем | чтение переписок |
| Когда используется | только `bootstrap` и `modules` | все остальные команды |

Разделение принципиально: API-ключ RetailCRM даёт доступ ко всему аккаунту,
а `mgBot`-токен — только к чатам. После `bootstrap` ключ можно вообще убрать
из конфигурации.

## Как выпускается токен

```
POST /api/v5/integration-modules/{code}/edit
  integrationModule[code]                              = mg_connector_prod
  integrationModule[integrationCode]                   = mg_connector_prod
  integrationModule[clientId]                          = mg-connector-prod
  integrationModule[name]                              = MG connector prod
  integrationModule[active]                            = true
  integrationModule[integrations][mgBot][refreshToken] = true
```

Флаг `refreshToken` — единственный способ получить токен программно: RetailCRM
обращается к MessageGateway, тот выпускает токен и возвращает его в ответе.

Формат ответа отличается между версиями RetailCRM, поэтому `extract_token()`
сначала пробует известные пути (`info.mgBot.token`,
`integrationModule.integrations.mgBot.token`), а затем обходит дерево ответа
в поисках строкового поля с `token` в имени. Найденные кандидаты можно
посмотреть — замаскированными — через `bootstrap --dump-response`.

**Перевыпуск отзывает предыдущий токен.** Поэтому перед выпуском коннектор
читает модуль и, если он уже привязан к MG, останавливается с предупреждением.
Обойти проверку — `--refresh` (осознанный перевыпуск) или `--force`.

## Пагинация MG

MG отдаёт списки страницами и не сообщает общее количество. Курсор — идентификатор
последнего элемента:

```
GET /chats?limit=100
GET /chats?limit=100&since_id=<id последнего элемента>
```

`MgClient.paginate()` инкапсулирует это и отдаёт ленивый итератор. Обход
останавливается, когда страница пришла неполной, пустой или курсор перестал
двигаться — последнее защищает от бесконечного цикла на нестандартном ответе.

Все методы возвращают итераторы: `export --limit 5` не станет вычитывать
тысячи чатов, чтобы взять пять.

## Модель данных

```
Канал (channel)          WhatsApp, Telegram, VK, e-mail…
  └── Чат (chat)         переписка с конкретным клиентом
        ├── Диалог       отрезок чата, назначенный на оператора или бота
        └── Сообщение    текст, файл, системное событие
```

`export.py` собирает из этого `Transcript` — чат вместе с сообщениями —
и нормализует каждое сообщение к плоскому виду: `direction` (`in`/`out`),
`author`, `text`, `time`, `attachments`. Исходный ответ MG сохраняется
в `raw_chat`, чтобы ничего не терялось.

## Обработка ошибок

`http.py` превращает HTTP-статусы в типизированные исключения:

| Статус | Исключение | Поведение |
|---|---|---|
| 401, 403 | `AuthError` | без ретрая — ключ или токен не тот |
| 404 | `NotFoundError` | без ретрая |
| 429 | `RateLimitError` | ретрай с экспоненциальной паузой |
| 5xx | `ApiError` | ретрай с экспоненциальной паузой |

Все они наследуются от `ConnectorError`, который CLI ловит на верхнем уровне
и превращает в короткое сообщение вместо трейсбека. Коды возврата: `0` — успех,
`1` — ошибка выполнения, `2` — проблема конфигурации.
