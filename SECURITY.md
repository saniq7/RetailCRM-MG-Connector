# Политика безопасности

## Что делает коннектор для защиты секретов

- API-ключи и токены выводятся только замаскированными: `abc123...wxyz`.
- Параметр `apiKey` вырезается из URL в логах, сообщениях об ошибках и трейсбеках.
- `.env` создаётся с правами `0600`.
- Ключ можно не хранить на диске: `bootstrap` запросит его интерактивно,
  минуя историю shell и список процессов.
- Внешних зависимостей нет — поверхность атаки через цепочку поставок минимальна.

## Что должны обеспечить вы

- Выдавайте API-ключу RetailCRM минимальные права: только integration modules.
- Не переиспользуйте один `mgBot`-токен на нескольких серверах: перевыпуск
  отзовёт его, и всё сломается. Каждой интеграции — свой `integrationModule.code`.
- Не коммитьте `.env`. В `.gitignore` он уже есть.
- Помните: выгруженные переписки содержат персональные данные клиентов.
  Каталог экспорта нужно защищать так же, как саму CRM.
- После `bootstrap` API-ключ RetailCRM можно удалить из `.env`: для чтения
  переписок достаточно `mgBot`-токена.

## Как сообщить об уязвимости

Не открывайте публичный issue.

Воспользуйтесь [приватным сообщением о безопасности GitHub](https://github.com/saniq7/RetailCRM-MG-Connector/security/advisories/new).
Опишите проблему, шаги воспроизведения и версию коннектора.

Ответ — в течение 7 дней.
